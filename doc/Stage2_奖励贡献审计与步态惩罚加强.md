## 主要问题

前脚高度贡献+4.644，占全部正贡献约37.24%。角速度跟踪+1.695、航向+1.439、机身高度+1.230、线速度跟踪+1.167、存活+0.982，构成稳定双支撑时的大部分收益。本轮不削减这些稳定性奖励，先按用户要求加强步态错误惩罚。

相位接触仅+0.179，接近“双脚始终接触、只在20%双支撑窗口得分”的理论+0.18。抬脚正奖励仅+0.092；欠抬脚惩罚−0.396，接近完全不抬脚时的整周期−0.4。全时刻中约78.76%仍出现“当前要求摆动的脚接触地面”；当前目标约80%时间属于单支撑窗口。这些实测共同说明后脚仍几乎全程双支撑，不是只有某一次抬脚峰值不足。

抬脚奖励采用1 cm误差宽度；6 cm目标峰值时脚仍在地面，指数因子exp(-6)约0.00248。旧规则虽有欠抬脚负项，却没有直接扣除相位接触错误：不换脚只是失去+0.9的匹配奖励。

## 已实施

只修改walk的训练默认配置，标记stage2_foot_support_v2；balance保留27项旧规则。

1. feet_clearance_deficit：权重−1改为−3，公式仍为sum(swing * (relu(target-sole_height)/0.06)^2)。
2. 新增phase_contact_error：权重−2，公式为mean(actual_contact != desired_stance)，对两只后脚取平均；接触阈值仍为竖直力>1 N。
3. 相位周期1.6秒、峰值6 cm、20%双支撑、正向相位奖励+0.9、抬脚奖励+1不变；其他奖励、足端支撑门控、接触终止、PD和PPO不变。
4. 两项负奖励都不乘高度、直立或承重门控，降低机身或短暂失去支撑不能直接关掉惩罚。

单支撑窗口中：该摆动的脚仍着地会扣分，该支撑的脚离地也会扣分；只抬错侧脚两者都错，扣分更高。双支撑窗口要求两脚落地，不会惩罚正常换脚停顿。左右目标随相位互换，单脚长期拖地无法持续满足要求。腾空同样存在缺失支撑惩罚，且原承重门控会取消主要正奖励。

理想化的峰值时刻（仅这两项）：

| 情况 | 加权惩罚 |
| --- | ---: |
| 双脚都落地，未抬脚 | −4.00 |
| 正确摆动脚离地3 cm、对侧支撑 | −0.75 |
| 正确摆动脚离地6 cm、对侧支撑 | 0 |
| 抬错脚到6 cm、应摆动脚仍落地 | −5.00 |

整周期双脚始终在地面：旧欠抬脚平均−0.4；新欠抬脚−1.2、相位错误−0.8，合计−2.0。计算采用周期中点采样，避免浮点相位边界影响。
