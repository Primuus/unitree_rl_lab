# 训练稳定性与续训学习率审计

2026-10-31。针对“训练总是不稳定，还能怎么优化”的分析。只做日志、checkpoint 和已安装算法源码核对，以及无训练的 CPU 恢复验证；未修改参数或启动训练。

## 首要发现：续训时两处学习率状态不一致

服务器安装 rsl-rl-lib 2.3.3。当前 scripts/train_v20.py 创建 OnPolicyRunner，再调用 runner.load(..., load_optimizer=True)。安装版本的 load 恢复模型、优化器和迭代计数，但没有将优化器学习率同步至 PPO.learning_rate。

真实 model_6489.pt 的 optimizer_state_dict.param_groups[0].lr = 0.0000759375。配置创建 PPO 时 learning_rate = 0.001。CPU 上建立同维度 ActorCritic/PPO，调用实际 OnPolicyRunner.load 后确认：

- current_learning_iteration：6489。
- alg.optimizer.param_groups[0]['lr']：0.0000759375。
- alg.learning_rate：0.001。
- 内部值与恢复的优化器值之比：13.1687。

验证使用 checkpoint 的 CPU 反序列化对象代替 torch.load 的返回值，其余 load 逻辑、策略加载和优化器加载均执行真实安装代码。未执行 optimizer.step，未创建测试文件，也未修改模型。

PPO.update 的 adaptive 分支根据 KL 对内部 learning_rate 乘/除 1.5，再将它写回每个 optimizer param_group。因此恢复的学习率不能保持到正常更新链路。第一批更新写入多少取决于当时 KL；本次未复刻原始 rollout，不能将 13.17 倍说成已测得的首批实际更新幅度。

来源：[RSL-RL v2.3.3 runner](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py)、[PPO](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/algorithms/ppo.py)。最终判断以服务器已安装源码及 CPU 复现为准。

恢复训练最初的日志会受随机 episode_length 和统计缓冲重建影响，不能用第 1 轮极短回合直接判退化。但第 50–100 轮仍持续短回合，且训练日志出现大量 body_contact 终止，值得优先检查续训更新，而非只解释为统计重置。

TensorBoard 的第十轮最初几轮 Loss/learning_rate 为 1e-5，这是每轮 PPO 完成多批更新后的值；它不代表第一批更新前没有学习率上跳。原先没有逐 mini-batch 的 KL / learning_rate 记录，无法从现有汇总日志恢复全部瞬态。

这里确认的是恢复状态缺失，及同时存在的训练退化。两者的因果贡献仍需同起点、同参数的短程对照，不能说已经解释了全部不稳定。重置分布、探索动作与相位初态也可能影响早期表现。

## 奖励信号显示另一类问题：站立保持，但踏步未学到

最后两轮末尾：
- 第九轮 contact 0.5278，feet_clearance 0.6286，feet_clearance_deficit -0.3903。
- 第十轮 contact 0.5186，feet_clearance 0.6194，feet_clearance_deficit -0.3851。

在高度门控开启、双脚足底始终不离地的理想条件下，当前公式整周期加权平均约为 contact 0.54、clearance 0.644、deficit -0.4。训练日志包含 episode 归一化和失败回合，不能逐项严格等同，但接近这些数值，与最终确定性评估中无连续交替抬脚的证据一致。

因此应区分两件事：恢复后策略暂时退化，以及策略重新稳定后仍主要双脚接地。修复学习率恢复是必要的实现修正，未必会自动解决踏步。

## 建议按顺序实施

1. 先修复训练入口的续训状态：runner.load 后，把 PPO.learning_rate 与恢复的 optimizer lr 同步；记录恢复前后值。保留当前奖励，做 50–100 轮同起点对照，观察是否还发生持续回合坍塌。这一轮不要同时改 clip、熵系数或多个奖励。
2. 若修复后仍有更新过猛，再考虑限制微调学习率上限，例如 1e-4，而不是恢复到从头训练用的 1e-3。最新 6988 保存 lr 为 5.0625e-5，直接设成 3e-4 反而可能增大步幅。desired_kl 0.01→0.005、clip 0.2→0.1 可作为后续各自独立的候选对照，暂不一次全改。
3. 每 50 轮固定条件评估，而不仅保存；以无摔倒、直立、前向误差、角速度、位置漂移和有效落脚选择 checkpoint。保留最终模型，也明确保存本轮验收表现最好的模型，避免用总奖励或“最后一个”代替质量判断。先固定一个 seed 比较，候选确定后再换 seed 复核。
4. 优化踏步时先做单变量接触奖励实验：摆动期必须让指定脚离地才给足接触奖励，支撑期保持接触；可比较整对接触匹配与当前逐脚平均。这样会减少双脚接地的部分奖励，也可能增加学习难度，需实测。保留现有欠抬脚惩罚作为对照，别再先加权重。
5. 若接触激励明确后仍抬不起来，再采用 2→4→6 cm 高度课程；升高依据有效交替落脚和漂移指标，不只依据迭代数。最终目标仍是 6 cm。若固定低高度也不学换脚，应回查奖励/动力学，不能用课程代替诊断。
6. 若训练稳定后确定性回放仍抖动，记录动作变化、关节速度和支撑脚滑移，再决定是否提高动作平滑约束或调整控制。暂不同时改 PD、滤波、动作缩放或固定前腿，以免改变动力学后无法归因。

建议第一轮只实施第 1 项并配套周期评估，短程验证后再决定后续。该方案与“继续原参数训练 500 轮”不同，重点是先消除已复现的续训不连续。
