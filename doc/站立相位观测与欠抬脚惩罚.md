# 站立相位观测与欠抬脚惩罚

按用户确认，在现有 6 cm 目标上增加摆动脚欠抬脚惩罚，并修正 balance 零命令时相位观测被关闭的问题。当前 balance 共 27 项奖励；walk 的 23 项奖励与命令门控时钟保持不变。

## 相位观测

此前奖励根据 `episode_length_buf` 交替指定左右摆动脚，但 Actor 和 Critic 的 `gait_phase` 调用了带 `moving` 门控的函数。balance 三轴零命令导致输入恒为 `[0,0]`，策略无法直接观察奖励所需的步态相位。

现在 balance 默认 `balance_gait_clock="always"`：Actor/Critic 的 12:14 均输入周期 1.6 s 的 `[sin(2πt/T), cos(2πt/T)]`，其中 `t=episode_length_buf×step_dt`，和抬脚目标使用同一时钟。环境复位从相位 0 开始。相位 0.25 为左后脚目标峰值，相位 0.75 为右后脚峰值。

Actor 56、Critic 155、动作 12 维不变，但这两维输入的语义发生变化。可以从 model_5990 恢复网络和优化器继续训练；不能据此认为旧策略已能利用新相位。现有镜像逻辑将 sin/cos 同时取反，对应半周期偏移，与左右后脚目标交换一致。

## 欠抬脚惩罚

新项 `feet_clearance_deficit`，初始权重 **-1.0**，是本次用户批准的新适配，并非参考工程原样奖励：

`cost = sum(swing_mask × (max(target_height - sole_height, 0) / 0.06)^2)`

仍乘现有逐环境高度门控 `height_score > 0.70`；奖励管理器再乘权重 -1.0 和控制步长 0.02 s。分母跟随目标峰值 `balance_step_height`，当前为 0.06 m。

- 仅惩罚相位要求摆动的后脚，支撑脚和双支撑时段不计这项惩罚。
- 目标是连续半正弦，不是摆动全程都要求达到 6 cm。
- 在目标峰值处，实际抬高 0 / 3 / 6 cm 对应加权值 -1 / -0.25 / 0（未计时间步和门控）。
- 实际足底高度继续使用训练 URDF 足端碰撞球参数，半径 0.022 m、局部偏移 (-0.002,0,0)，不把两脚相对高度当成离地高度。
- 达到或超过目标时，欠抬脚惩罚归零；原有 `feet_clearance=+1.0` 指数高度奖励保留，仍对偏离目标、包括超过目标评分。

保持 contact=+0.9、零转向惩罚 -0.2、航向保持 +1.5、滑移惩罚 -0.5、20% 双支撑，以及控制/PPO 等参数。没有继续提高正奖励权重。

## 旧策略回放与来源记录

训练 `provenance.json` 的 `layout.gait_clock` 记录模式与周期。新版 balance 为 `always`，walk 为 `moving_only`。

- Isaac 评估默认 `--gait_clock auto`：读取 checkpoint 所在训练目录的 `params/provenance.json`；旧来源中没有该字段时按历史 `moving_only`、1.6 s 回放。无策略 smoke 使用新配置。诊断时可显式指定 balance 的 `--gait_clock always` 或 `moving_only`，实际模式写入结果，覆盖模式也单独记录。
- MuJoCo 默认 `config.json` 中 `gait_clock_mode=auto`：从所选策略的 `exported/` 相邻 `params/provenance.json` 读取。旧 model_5990 保持零命令时的零相位输入；新策略自动打开相位。运行时解析配置副本，不改写旧模型元数据。外部无来源文件的策略必须在部署配置中明确指定模式。
- 下载新导出策略时保留配套来源文件。不能仅替换权重、再手工把所有旧策略的相位强制打开。
- MuJoCo 按仿真时间计算相位，按 R 复位后重新从 0 开始；策略周期保持 20 ms。
