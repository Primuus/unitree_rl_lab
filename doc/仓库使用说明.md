正式训练默认使用 4096 个并行环境，可通过 `--num_envs` 覆盖。短训练示例使用 64 个环境：

```bash
./ry_python.sh scripts/train_v20.py --stage balance \
  --num_envs 64 --max_iterations 3 --run_name smoke \
  --headless --device cuda:0
```

训练产物位于 logs/rsl_rl/ry_unitree_go2_handstand/，包括 checkpoint、参数、来源快照与导出策略。

当前 balance 入口使用混合命令：50% 零速度踏步、50% 前进 0.05～0.10 m/s，横向和转向为零，每 10 秒及重置时重采样。walk 保留固定 0.2 m/s；两入口统一使用现有 27 项奖励、始终启用相位、6 cm 抬脚和 20% 双支撑，线/角速度跟踪分母分别为 0.0025/0.04。相位接触 +0.9、抬脚 +1.0、欠抬脚 -1.0、滑移 -0.5、零转向 -0.2、航向保持 +1.5 均保留。default_pos 和 symmetric_joints 现仅约束前腿（权重各 -0.1），允许后腿交替屈伸；后腿髋关节偏移、限位和动作平滑仍保留。网络、PD 和 PPO 不变。

高度奖励现为 exp(-abs(h-0.52)/0.05)，权重仍为 +1.5。速度跟踪仅要求机身直立方向余弦 >0.94；相位接触和抬脚正奖励在该直立门控基础上再乘平滑高度系数 0.3+0.7*clamp((h-0.43)/0.07,0,1)，即 ≤0.43 m 保留30%、≥0.50 m 保留100%；欠抬脚惩罚不设高度门槛，零转向惩罚只保留 abs(command_yaw)<0.1 条件。原高度分数仅供未改动的 ang_xz、symmetric_joints、default_pos_reward 使用，航向保持的软门控不变。详见[高度奖励与任务门控](高度奖励收紧与任务门控解耦.md)及[新增平滑高度系数与诊断](步态奖励平滑高度系数与关节跟踪诊断.md)。

混合命令续训 500 轮、每 50 轮保存 checkpoint（命令示例，本轮未启动）：

```bash
./ry_python.sh scripts/train_v20.py --stage balance \
  --resume logs/rsl_rl/ry_unitree_go2_handstand/2026-10-31_09-53-03_balance_height_gate_continue500/model_2497.pt \
  --num_envs 4096 --max_iterations 500 --save_interval 50 \
  --run_name mixed_zero_forward --headless --device cuda:0
```

`--save_interval` 仅覆盖本次运行的保存间隔；不传时沿用参考配置的 100 轮。checkpoint 留在本次训练目录，需要时通过 `scripts/eval_v20.py --stage balance --checkpoint <checkpoint路径>` 查看。

站立验收现使用 [stationary-v2 条件](站立验收条件.md)，新增转动角速度、连续航向偏差、最大水平位移与水平路径约束；逐环境判断并输出失败原因。评估需分别报告零命令与前进命令结果。

按用户要求，balance 已加入 [转动约束奖励](站立转动约束奖励接入说明.md)：世界竖直轴零转向误差平方惩罚 -0.2，固定世界 +X 航向保持 +1.5（宽度 0.6 rad）。两项已用于此前续训；观测接口与已有 checkpoint 兼容。

当前 balance 启用相位 sin/cos，并加入归一化欠抬脚惩罚，见 [相位与欠抬脚接入说明](站立相位观测与欠抬脚惩罚.md)。Actor/Critic 维度保持 56/155，但相位输入语义改变。旧模型评估与 MuJoCo 默认根据策略来源配置恢复旧相位模式；续训使用新模式。
