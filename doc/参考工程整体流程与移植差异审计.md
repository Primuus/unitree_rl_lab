# 参考工程整体流程与当前移植差异审计

2026-10-31。范围：参考工程 My_unitree_go2_gym 的 go2_handstand，与当前 ry_unitree_rl_lab balance 实现及 model_6988 评估。原工程 /workspace/unitree_rl_lab 不作为本次比较对象。本次只分析，不修改训练参数或启动训练。

## 结论与证据边界

当前实现继承了参考奖励主体、PD 和 PPO 参数，但观测、任务分布、初始化、机器人资产以及站立阶段的步态奖励已经不同，属于经过多轮改造的迁移实现，不是完整复现。

参考仓库 README 的 TODO 本身记录了 stand 关节抖动、静止后退等问题。我们没有将参考 checkpoint 放入同一套零命令、20 s、逐环境验收中测试，不能假设它已经满足我们的静止标准。最近续训前向误差下降而转动变大，也不能单独证明问题只是未收敛或某一个奖励有错。

来源：[参考 README](https://github.com/yusongmin1/My_unitree_go2_gym#todo-list)。

## 参考工程实际流程

该任务是 Isaac Gym + legged_gym + 标准 PPO，不是 AMP 模仿学习任务。12 个关节全部由策略控制；MLP 512/256/128；4096 环境，每轮每环境 24 步，默认配置 15000 轮。控制周期 20 ms（仿真 5 ms、decimation=4），动作目标为默认关节角 + 0.25×动作，PD 为 Kp=40、Kd=1。上述主要控制/PPO设置与当前工程基本一致。

参考从正常四足朝向、机身高度 0.42 m 初始化，关节为默认角度的 0.5–1.5 倍，并随机初始速度。训练命令包含前后运动与转向，前向范围 -0.2–0.6 m/s，10 s 重采样，另有零线速度采样；heading_command 将目标航向误差转成转向指令。不能把其 20% 全零采样直接当成全程零转向，因为随后回调会更新转向指令。没有当前这种独立 balance 全零命令、再 walk 固定 0.2 m/s 的流程。

奖励组合引导机身直立、前脚抬高、跟踪运动命令、后脚单支撑和摆动，同时约束动作变化、力矩、关节和姿态。默认有质量、重心、PD、关节摩擦/阻尼/armature、动作延迟、外力推扰等随机化。

来源：[参考任务配置](https://github.com/yusongmin1/My_unitree_go2_gym/blob/main/legged_gym/envs/Go2_Stand/Go2_Handstand/Go2_Handstand_Config.py)，[参考任务源码](https://github.com/yusongmin1/My_unitree_go2_gym/blob/main/legged_gym/envs/Go2_Stand/Go2_Handstand/Go2_Handstand.py)。

## 名称应以实际支撑脚为准

当前参考源码的 go2_handstand 配置 contact_foot=[RL_foot,RR_foot]，前脚受悬空和高度奖励约束，目标重力 [-1,0,0]，实际为后腿支撑。

go2_leggedstand 则 contact_foot=[FL_foot,FR_foot]，目标重力 [1,0,0]，实际为前腿支撑。英文名称及部分“前腿支撑”注释与当前配置不一致。此前若按英文名称解释 handstand/leggedstand，需要以这里的配置核对结果纠正。

来源：[Leggedstand 配置](https://github.com/yusongmin1/My_unitree_go2_gym/blob/main/legged_gym/envs/Go2_Stand/Go2_Leggedstand/Go2_Leggedstand_Config.py)。

## 对学习目标影响最大的差异

| 项目 | 参考 go2_handstand | 当前 balance |
| --- | --- | --- |
| 任务分布 | 混合前进、后退、转向、零线速度 | 始终零命令，原地抬脚 |
| 初始化 | 四足姿态、较大随机状态 | 直接直立，目标角度附近小扰动 |
| Actor / Critic | 45 / 86 | 56 / 155 |
| 相位输入 | Actor 没有显式相位，奖励内部有周期 | 目前 balance 始终输入 sin/cos |
| 相位接触 | 恰好一只后脚接触才给分 | 逐脚匹配期望接触，20% 双支撑 |
| 抬脚评分 | 仅摆动脚，exp(-10×高度误差) | 两脚均值，exp(-高度误差/0.01) |
| 速度跟踪分母 | 线/角均 0.25 | 线 0.0025、角 0.04 |
| 附加项 | 无当前四个附加项 | 滑移、零转向平方、航向保持、欠抬脚 |
| 随机化 | 质量/重心/PD/延迟/推扰等 | 主要为材质随机化和重置扰动 |

参考 Actor 无显式相位也无基座线速度；当前额外提供线速度、相位、航向、后脚相对高度与载荷。Critic 内容也由随机参数信息改为包含高度扫描等，不是简单增加几个无关维度。

上述差异说明输入、环境转移和目标函数均发生变化，但不能仅凭差异存在认定哪一项是失败原因。需要对照实验。

## 接触与抬脚：权重大不等于同一个目标

参考接触项为 `0.3 * (后脚接触数量 == 1)`；双脚接地没有此项奖励。当前为 `0.9 * mean(实际接触 == 相位期望接触)`。

当前在单支撑目标阶段，若双脚都不离地，仍有一只脚匹配，获得 0.45；在 20% 双支撑阶段则获得 0.9。假设高度门控一直开启、两脚始终接触，整周期平均为 0.54。参考该项为 0。当前项能区分左右相位，但对双脚不动给了部分分数。

抬脚不仅权重 0.4→1.0，还把指数宽度从 0.1 m 缩至 0.01 m、评分对象从摆动脚改为双脚、加入双支撑。目标峰值同为 6 cm，并不意味着相同的奖励曲线。

为避免仅凭部分奖励误判，按双脚足底高度理想为零、门控开启、周期均匀采样，数值核算当前三项的加权周期平均：
- contact：+0.5400。
- feet_clearance：+0.6440。
- feet_clearance_deficit：-0.4000。
- 合计：+0.7840，尚未乘控制步长 0.02。

如果理想完成全部目标，三项合计可达 +1.9；所以不能据“脚不抬也有分”认定不抬脚是全局最优。这些数值只表明评分结构改变，策略还需权衡换脚过程中的平衡、速度、动作变化和跌倒代价。当前名义抬脚收益差也并不比参考更小。

零速度跟踪同样收紧了很多：仅前向误差为 0.1 m/s、其他误差为零时，未加权指数分数从 exp(-0.01/0.25)=0.961 变为 exp(-0.01/0.0025)=0.0183。这改善了对漂移的敏感度，也会惩罚换脚时的瞬时速度；与参考行走任务的奖励权衡不同。

参考左右关节对称项确实包含后腿，可能与交替动作产生权衡，但它在参考里也存在，不能直接视为移植错误。feet_height_symmetry 实际读取前脚高度，不应误说成强制后脚同高。

对应当前文件：`ry_go2_biped_walk_v20/stepping_rewards.py`、`gait_mdp.py`、`gait_env_cfg.py`、`reference_rewards.py`。

## 机器人与仿真并未完全对齐

直接解析参考 go2.urdf 和服务器当前 unitree_ros 原始 URDF，得到：

| URDF 标称参数 | 参考模型 | 当前模型 |
| --- | ---: | ---: |
| 所有 link 质量之和 | 15.019 kg | 16.087 kg |
| calf effort | 35.55 N·m | 45.43 N·m |
| calf velocity | 20.07 rad/s | 15.70 rad/s |
| 足底碰撞球半径 | 0.022 m | 0.022 m |

当前 robot_cfg.py 从当前 URDF 读取关节上限；不是只更换外观。上述质量是 URDF 标称和，不混同于训练随机化后的每环境实测质量。

引擎从 Isaac Gym 变为 Isaac Lab / Isaac Sim，配置中的求解器位置/速度迭代也从 4/0 变为 8/4；碰撞导入和随机化链路不同。这些是需要核对的动力学差异，尚无实验能证明它们是主要原因，不应把所有问题推给仿真器。

参考资产：[go2.urdf](https://github.com/yusongmin1/My_unitree_go2_gym/blob/main/resources/robots/go2/urdf/go2.urdf)。当前资产：服务器 `/workspace/unitree_ros/robots/go2_description/urdf/go2_description.urdf`。

## 训练历史如何影响判断

当前 checkpoint 编号接近 7000，不等于在现在这套目标上连续训练了 7000 轮。6 cm + always 相位 + 欠抬脚 + 新转动约束组合只经历了最近两轮，共 1000 次更新。更早策略主要学习双脚接地的站立行为，早期零命令下没有开放相位输入。

因此“尚未充分适应新目标”是合理假设，但“继续 500 就一定会解决”没有证据。当前只完成单个 seed，且没有对参考模型做同条件验收。参考默认 15000 是配置预算，不能当成已知收敛所需轮数。

最近同条件评估：6489→6988，前向误差 0.06335→0.02329 m/s，世界 Z 绝对角速度 0.04708→0.12048 rad/s，站立验收均 0/16，连续交替步数条件均 0/16。表现仍在目标之间变化，尚不能宣布合格收敛。

## 建议的验证顺序

1. 先建立参考 checkpoint 的相同零命令与运动命令评估基线，确认它实际能做到什么，避免把演示中的行走表现当成严格静止表现。
2. 在当前仿真里明确保留哪些必要接口适配，先核对资产/控制，再用最少任务改动建立可复现基线；若要更换当前机器人资源，应单独明确，不在此次分析中修改。
3. 在零命令与小前进命令下比较单支撑、有效落脚和漂移，分辨“不会换脚”还是“零命令下选择不换脚”。
4. 对接触公式、抬脚评分对象/宽度做单变量实验，并检查各项实际奖励贡献。保留现有阶段结果，不用一次继续调多项来代替对照。
5. 对新目标给予足够训练时间，用同条件验收追踪，而不是只看累计轮数或总奖励。
