## 提高到0.5后最直接的阻碍：速度奖励过窄

现有线速度奖励使用body -Z及body Y投影：
2.5 × exp(-(前向误差平方+横向误差平方)/0.0025)，再乘直立与足端支撑条件。

0.0025是此前原地站立逐步收紧的值，误差尺度sqrt(0.0025)=0.05 m/s。忽略侧向误差、假定姿态/支撑门控均为1，目标0.5时的加权奖励上界为：

| 实际前向速度m/s | 加权速度奖励 |
| --- | ---: |
| 0.02 | 2.36e-40 |
| 0.10 | 4.01e-28 |
| 0.20 | 5.80e-16 |
| 0.30 | 2.81e-7 |
| 0.40 | 0.04579 |
| 0.45 | 0.91970 |
| 0.50 | 2.50000 |

这是逐状态公式示例，不能把平均速度直接代入后当作实测平均奖励。它说明从当前低速向目标小幅加速时，PPO几乎得不到可辨的速度奖励改善；不是说PPO对奖励公式直接求动力学梯度。

补充只读评估：model_6988、命令0.5、16环境20秒、seed=1，保留已保存v2奖励和关闭噪声的play环境：
- 平均前向速度−0.03013 m/s，平均绝对误差0.53013 m/s。
- 平均高度0.51246 m，单支撑1.42%，左右有效落地均0.0625次/环境。
- 0/16接触失败，全部完成20秒。
- 去掉前2秒，14400个有效环境步的实际线速度加权奖励率仅8.40764e-10。

该策略只在0.05命令训练过，0.5属于未训练命令；以上是当前策略的响应探测，不是0.5训练后的效果，也不能据此证明目标不可达。

## 其他阻碍与建议顺序

1. **学习阶段的速度反馈。** 建议先把walk速度奖励宽度从站立值分离，优先对照已保存参考工程的tracking_sigma=0.25，让低速到目标之间存在连续收益；形成跟踪后再收紧。balance的严格静止宽度可保持。此次未修改该项。
2. **从双脚承重到单腿承重缺少连续引导。** 当前phase_contact_error只比较足端力是否越过1 N。摆动脚从承重约一半逐渐卸载到略高于1 N，接触错误仍相同；脚没离地时高度惩罚也几乎不变。虽有相位观测，网络仍可以保持既有双支撑动作。后续可检查摆动期载荷曲线，考虑让部分卸载也获得反馈，再接入现有6 cm目标；不应把“相位已输入”当成“策略必然按相位运动”。
3. **速度与周期不协调。** 当前完整周期1.6 s，左右换脚间隔约0.8 s。若无滑动以0.5前进，机身每周期前进0.8 m，左右相邻换脚间前进约0.4 m；每脚支撑约0.96 s，对应机身前移0.48 m。这对直立后腿的可用摆幅要求较大。应核对运动学并考虑缩短周期；不能把本计算当成已经证明0.5不可达。此次周期仍1.6 s。
4. **旧站立分支与探索。** 从长期站立权重连续微调，双支撑模式已有较高姿态/高度/存活收益，较难通过随机动作找到协调承重转移。需要保持统一评估，对比连续训练趋势和必要的探索设置，而不是仅以总奖励高认定“不想探索”。尚未做PPO改动对照，因果未证实。
5. **动作平滑及碰撞终止。** 加速和迈步可能增加动作变化成本，非足端接触也会结束回合，但目前没有证据表明这两项单独构成硬速度上限。保留足端支撑要求，先修正速度反馈和检查承重转移；未放松接触或高度约束。

观察和奖励的速度坐标有细微区别：观测/评估按水平航向，参考奖励近似用body -Z/Y，机身倾斜时不完全一致。直立时符号对应，现有证据不足以将它认定为此次速度停滞的主要原因；后续提速时宜进一步量化。
